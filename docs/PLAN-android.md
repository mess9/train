# План: нативное Android-приложение рядом с PWA

План от 2026-11-21, этап 1 сделан. Зачем: PWA рисует Compose в canvas браузера, прокрутка и жесты
заметно уступают нативным (см. обходы в CLAUDE.md про `pointermove` и захват жеста в `Page`).
ADR 0003 этот выход предусматривал: «смена таргета, а не переписывание».

**Цель:** один UI-код — две сборки. PWA остаётся как есть (обновление перезагрузкой, e2e), APK
ставится на телефон владельца. Переиспользование — пока оно не требует толстых костылей.

Опора — скилы в `.claude/skills/`: `kotlin-tooling-agp9-migration` (раскладка модулей под AGP 9)
и `jetpack-compose-performance` (аудит перерисовок).

## Что есть сейчас

- `app` — KMP, только `wasmJsMain`: 17 файлов, ~5 100 строк. Чистый Compose почти весь; браузер
  трогают `Bridge.kt` (мост с `index.html`), `AppState.kt` (адрес сервера из `location`,
  «назад» через `history`, событие `online`), `Main.kt` (`ComposeViewport`), `Media.kt`
  (гифка — `<img>` поверх canvas).
- `core`, `client` — KMP `jvm` + `wasmJs`. `health-sync` уже берёт jvm-вариант `client` в
  Android — значит, общий код в Android заходит без нового таргета у них.
- AGP 9.5.1 в каталоге, Kotlin встроенный, плагин Android объявлен в корне (CLAUDE.md).
- e2e (ADR 0012) ходит по дереву доступности Compose, а не по DOM-вёрстке. На Android Compose
  отдаёт ту же семантику (тексты, `contentDescription`, рамки) в `AccessibilityNodeInfo` —
  отсюда шанс переиспользовать сценарии.

## Раскладка модулей

По скилу AGP 9: KMP и `com.android.application` в одном модуле нельзя (Path B), а KMP-библиотеке
нужен `com.android.kotlin.multiplatform.library` с настройкой в `kotlin { android { … } }`
(Path A).

```
app/          KMP-библиотека UI: commonMain (экраны, AppState), wasmJsMain (мост, точка входа PWA,
              index.html, sw.js), androidMain (actual моста). Wasm-исполняемый остаётся здесь
android/      com.android.application: MainActivity, манифест, иконки, подпись, версия
```

Полную перестройку (Path C: `shared` + `webApp` + `androidApp`) скил называет необязательной.
Не делаем: переименование тронет `server:appDist`, `Dockerfile`, e2e и CLAUDE.md, а пользы не
даст — wasm-исполняемый в KMP-библиотеке AGP 9 не запрещает.

Учесть из скила: `BuildConfig` в KMP-библиотеке нет — номер сборки передаёт `android/` при
запуске; `androidResources { enable = true }` не нужен, пока нет Compose-ресурсов (картинки с
сервера, иконки рисуются). По матрице версий IntelliJ IDEA 2026.1 AGP 9 не поддерживает —
Android-часть открывать в Android Studio, если IDEA споткнётся.

## Этапы

### 1. Общий код в `commonMain` — PWA не меняется

- Перенести экраны и `AppState` в `commonMain`; браузерное — за `expect`/`actual` в
  `wasmJsMain`, где останется нынешний код без изменений поведения.
- Швы, которые появятся в общем коде:
  - `Platform` — то, что сейчас в `Bridge.kt`: вибрация, звук, экран не гаснет, высота
    клавиатуры, фото, дата, видимость, номер сборки, `reload`, `openLogin`;
  - `Storage` уже есть в `core` — `LocalStorage` просто уезжает в `wasmJsMain`;
  - навигация «назад»: `AppState` держит стек, `window.history` прячется за интерфейс
    (`pushed`/`popped`); на Android — `BackHandler`;
  - сеть: событие «сеть появилась» и адрес сервера (`location.origin` → параметр);
  - движок Ktor (`Js` / `OkHttp`) — параметром в `AppState`;
  - гифка: `expect @Composable fun Gif(…)` — в вебе нынешний `<img>` поверх canvas.
- В `app` добавить Android-таргет (Path A).
- **Проверка:** `:app:compileKotlinWasmJs`, `./gradlew e2e` зелёный — PWA не сломалась.
- **Docker:** проверено — `docker build --target test` проходит без SDK: AGP настраивает `app` и
  без него, а сборка сервера Android-задач не запускает. SDK в `Dockerfile` — на этапе 4, вместе
  со сборкой APK.

**Сделано (2026-11-21).** Экраны и `AppState` — в `commonMain`, всё платформенное — `expect` в
`Platform.kt`: функции моста, `DeviceStorage`, адрес сервера, HTTP-клиент, `decodeImage`, события
«сеть появилась» и «на экране», `BackStack` вместо `window.history`. PWA — `Bridge.kt` (прежний
код) и `WebMain.kt`; Android — `Platform.android.kt`, заглушки. Гифка осталась функциями
`showGif`/`hideGif`, а не `@Composable`: на этапе 3 решить, нужен ли `expect @Composable`. По
пути починены два давних падения e2e: у кнопок оценок после перехода на пиктограммы пропала
подпись, а `compare` по умолчанию отдаёт текст (ADR 0014).

### 2. Пробный APK — стоит ли дальше

- Модуль `android/` (Path B): `MainActivity` с `setContent { Root(app) }`, OkHttp, хранилище —
  `AtomicFile` в `filesDir` (запись синхронная и целиком, как требует ADR 0007), адрес сервера,
  ключ и сервисный токен Cloudflare Access — экран настроек как в `health-sync` (вставить ссылку
  `…/#key=…`).
- Остальной мост — заглушки: фото «недоступно», гифка — статичная картинка.
- Сборка `release` с R8 — скил по производительности: отладочную сборку не мерить, ART в ней
  медленный.
- **Ворота:** владелец проводит на APK одну тренировку. Плавнее заметно — этап 3; нет —
  останавливаемся, этап 1 не мешает PWA.

### 3. Платформенные функции

Каждая — отдельный `actual` в `androidMain`, общий код не трогается.

| Что | Android |
|---|---|
| вибрация (`Haptic`) | `Vibrator` + `VibrationEffect.createWaveform` |
| сигнал таймера | `ToneGenerator` или `SoundPool` |
| экран не гаснет | `FLAG_KEEP_SCREEN_ON` на время тренировки |
| высота клавиатуры | `WindowInsets.ime` |
| «назад» | `BackHandler` / `OnBackPressedDispatcher` |
| сеть появилась | `ConnectivityManager.NetworkCallback` |
| видимость | жизненный цикл `Activity` |
| дата | `DatePickerDialog` |
| фото | `PickVisualMedia` и `TakePicture` (+ `FileProvider`), сжатие `Bitmap` → JPEG, дата снимка из EXIF |
| гифка | Coil 3 + `coil-gif` (Android 9+, у нас `minSdk` 28) с заголовком ключа |
| замок «одна вкладка» | не нужен — `held` всегда |
| вход Cloudflare | сервисный токен из настроек; `ACCESS_LOGIN` ведёт на экран настроек |

Самое крупное — фото: камера, галерея, сжатие, EXIF. Остальное — по нескольку строк.

**Одна активная тренировка на устройство.** На телефоне APK — основное, PWA — запасное (и для
компьютера). Сейчас замок `active-workout` есть только между вкладками браузера (Web Locks).
Нужен такой же на сервере: начатую тренировку ведёт одно устройство, второе показывает «идёт на
другом устройстве» и может её забрать. Небольшая доработка сервера и протокола (ADR 0007).

### 4. Доставка и обновления

Главное отличие от PWA: APK отстаёт от сервера. Пуш в `main` обновляет сервер и PWA сразу, а
APK — только когда Obtainium его поставит.

- **Сборка в Jenkins:** Android SDK — в `Dockerfile` (только сборка, в готовый образ сервера не
  попадает), лучше отдельной стадией для APK: серверу SDK не нужен, и его сборка не должна
  ждать установки SDK. Отдельная цель собирает `:android:assembleRelease`.
- **Релиз в Gitea** — только если пуш в `main` затронул `app/`, `android/`, `client/` или
  `core/`. Номер версии — из `version` в `gradle.properties` и числа коммитов (ADR 0009),
  `versionCode` растёт с каждым релизом. Jenkins нужен токен Gitea с правом на релизы.
- **Obtainium** на телефоне следит за релизами репозитория и ставит новую версию поверх.
- **Подпись** — отдельный release-ключ в учётных данных Jenkins, резервная копия у владельца;
  в репо и образ не попадает. Потерян ключ — обновление не встанет, переустановка сотрёт
  телефонные данные, в том числе неотправленную очередь. Локальные сборки — отладочным ключом с
  `applicationIdSuffix = ".debug"`: ставятся рядом с боевой и ей не мешают.
- **Совместимость API специально не закладываем:** приложение одно и своё. Несовместимое
  изменение API — значит, сразу обновить APK. Опасный момент — деплой посреди тренировки: такие
  изменения не выкатывать перед тренировкой.

### 5. e2e на Android

Сценарии `workout.spec.js` и `offline.spec.js` написаны через класс `Phone` (`e2e/lib.js`):
`tap`, `see`, `fill`, `rows`, `rate`, `menu`. Его поиск — по ролям, текстам и рамкам, это есть и
в дереве доступности Android.

- Второй драйвер `Phone` поверх Appium UiAutomator2 (WebdriverIO, тот же Node): узлы по
  `text`/`content-desc`, рамки по `bounds`, нажатие по координатам, ввод — `setValue` (кириллицу
  `adb input text` не умеет). Сценарии и стенд (`stand.js`) общие.
- Офлайн — авиарежим эмулятора вместо `context.setOffline`.
- Фото без системного диалога: в вебе тест подменяет `window.bridge.pickPhoto`. На Android нужен
  крючок в `debug`-сборке (файл из интента) — небольшой и вне боевой сборки.
- Нужен эмулятор Android (на Windows — WHPX), только локально, как и серверные тесты.
- **Граница костыля:** условия «если Android, то…» живут только в драйвере, сценарии их не
  знают. Если без них в сценариях не обойтись — значит, расходится поведение приложения, и
  чинить надо его, а не тест.

### 6. Аудит производительности общего кода — параллельно, полезен обоим

По скилу `jetpack-compose-performance`, с чтением нужного `references/*.md` перед каждой
правкой (так требует скил). Кандидаты: `WorkoutScreen.kt` (тик таймера не должен пересобирать
экран — чтение состояния в лямбдах `offset`/`graphicsLayer`), `Reorder.kt` (смещения при
перетаскивании — `Modifier.offset { }`), `Charts.kt` (`drawWithCache`), `Theme.kt`
(`Modifier.composed` → `Modifier.Node`), ленивые списки — `key` и `contentType`.
Учесть: у нас Compose 1.12 — `computedStateOf` из скила (1.13+) пока нет.

Мерить до и после: PWA — трейс Chrome DevTools на телефоне; APK — `adb shell dumpsys gfxinfo`
(доля janky-кадров).

## Решено (2026-11-21)

1. **Android SDK — в Docker-сборке**, ставится на этапе 4. Нужен в любом случае: Jenkins собирает
   APK для Obtainium.
2. **Обновления — Obtainium + релизы Gitea**, своей раздачи с сервера нет.
3. **Релиз** — только при изменении кода APK (`app/`, `android/`, `client/`, `core/`).
4. **Подпись** — release-ключ в Jenkins, копия у владельца; локальные сборки — `.debug`.
5. **Совместимость API не закладываем**: несовместимое изменение — сразу новый APK.
6. **e2e** — общие сценарии, второй драйвер `Phone` на Appium.
7. **`health-sync` не объединяем**: остаётся отдельным маленьким приложением на View.
8. **APK основное, PWA запасное**; одну тренировку ведёт одно устройство — замок на сервере.

Ещё не решено, по умолчанию: ключ и сервер в APK — вставить ссылку `…/#key=…`, как в
`health-sync`, без сканера QR.

Дальше — ADR 0016 (клиент: PWA и APK из одного кода) и правки ADR 0003, DESIGN.md
(«Клиент»), CLAUDE.md (сборка APK).
