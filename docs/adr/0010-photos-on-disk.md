# 0010. Фото прогресса — на диске сервера

Дата: 2026-11-05. Статус: принято. Заменяет «Фото — Garage» в DESIGN.md.

## Решение

- Файл — на диске, в папке `TRAIN_PHOTOS_PATH` (в контейнере `/photos`, на хосте по умолчанию
  `/mnt/safe_storage/data/train/photos`, bind-том, владелец `1000:1000`). Путь —
  `<папка>/<userId>/<photoId>`, без расширения: тип хранится в базе. В базе — таблица `photo`:
  когда снято (`takenAt`), тип, размер, SHA-256, ракурс, заметка, тренировка, корзина.
- **Загрузка** — `PUT /api/photos/{id}` с файлом в теле, id даёт клиент (UUIDv7, как у всех
  записей). Параметры — в query: `takenAt` (ISO 8601 или `YYYY-MM-DD` — полдень того дня; можно
  задним числом), `pose`, `note`, `workoutId`. Повтор с тем же файлом — `200` с тем же ответом,
  под тем же id другой файл — `409`.
- **Проверки**: размер — не больше `TRAIN_PHOTOS_MAX_BYTES` (по умолчанию 15 МБ), иначе `413`;
  тип — по первым байтам файла, не по заголовку: JPEG, PNG, WebP, HEIC/HEIF, иначе `415`;
  пустое тело — `400`. Файл сначала пишется во временный в `<папка>/.tmp` и переносится
  атомарно: оборванная загрузка не оставляет половину фото.
- **Отдача** — `GET /api/photos/{id}/file`: содержимое под id не меняется, поэтому
  `Cache-Control: private, max-age=31536000, immutable` и `ETag` — SHA-256. Ключ — как у всего
  API (ADR 0008).
- **Удаление** — в корзину (`DELETE`, `POST …/restore`), файл остаётся. `POST /api/trash/purge`
  стирает строку и файл.
- Хранилище за классом `PhotoFiles`: при переезде в S3 меняется он, API — нет.
- Путь не задан — API фото отвечает `503`, остальное работает.

## Почему

Сервер один, фото — десятки в год на человека. Garage — ещё один сервис в compose, свои
ключи доступа и свой бэкап. Папка на `/mnt/safe_storage` попадает в бэкап вместе с остальными
данными сервера, тесты обходятся без LocalStack и S3-клиента. Файл отдаёт тот же API с той же
проверкой ключа — отдельные права на бакет и подписанные ссылки не нужны.

## Отвергнуто

- **Garage / MinIO (S3).** Оправдан при нескольких серверах или больших объёмах — ни того ни
  другого нет. Интерфейс `PhotoFiles` оставляет путь.
- **Фото в Postgres (`bytea`).** Раздувает дампы базы, которые уходят в ночной бэкап целиком.
- **`multipart/form-data`.** Лишний разбор и лишний слой в клиенте: метаданных мало, они
  помещаются в query.
