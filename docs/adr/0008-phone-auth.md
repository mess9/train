# 0008. Авторизация на телефоне

Дата: 2026-11-01. Статус: принято.

## Решение

**Ключ.**
- Первый запуск — экран «Подключение». Адрес не нужен: PWA отдаёт тот же сервер.
- Ключ вставляют руками или сканируют QR. `gym admin key --qr` выводит ссылку `…/#key=…`:
  фрагмент URL не уходит на сервер и не остаётся в его логах.
- Смена ключа — в настройках.
- Ответ `401` → экран ключа, очередь не трогаем.
- Очередь привязана к `userId`. С ключом другого пользователя приложение ничего из неё не
  отправляет и предупреждает об этом. Поэтому очередь уходит только после того, как `/me`
  в этом запуске подтвердил владельца ключа. Новый ключ проверяется до того, как им что-то
  отправят.

**Ключ и Cloudflare Access.**
- Есть `Cf-Access-Jwt-Assertion` → сервер проверяет подпись по JWKS команды. Почта из JWT
  должна совпасть с почтой владельца ключа, иначе `403`.
- Сервисный токен (CLI, агент) — в JWT нет почты, пользователя определяет ключ.

**Картинки и фото.** Compose/Wasm сам загружает картинки нашим HTTP-клиентом, поэтому заголовок
с ключом добавляется автоматически. Анимированный gif Compose не проигрывает. Его показываем
HTML-`<img>` поверх canvas, через `blob:`-URL, полученный тем же запросом с ключом.

**Различение ошибок.** Запросы идут с `redirect: 'manual'`.

| Ответ | Что это | Что видит владелец |
|---|---|---|
| сетевая ошибка | нет сети | «офлайн», очередь ждёт |
| `opaqueredirect` | истекла сессия Access | «нужен вход», кнопка открывает страницу целиком |
| `401` / `403` от API | проблема с ключом | экран ключа |
| `5xx` | ошибка сервера | повтор с паузой |
| `409` | конфликт версий | по ADR 0007 |

Оболочку приложения отдаёт service worker, поэтому при истёкшей сессии Access тренировку
можно вести дальше.

## Почему

Без этого ключ некуда ввести. Истёкшую сессию Access не отличить от отсутствия сети: fetch
уходит по редиректу на чужой домен и падает с ошибкой CORS. Обычный `<img src>` не добавит
заголовок с ключом.
