# 0015. Сон, пульс, шаги — своим Android-приложением из Health Connect

Дата: 2026-11-15. Статус: принято. Дополняет 0002 (аналитика на сервере) и 0014 (текст для агента).

## Контекст

Тренеру нужен фон восстановления: сколько и когда владелец спит, ночной пульс, шаги. Данные
пишет браслет через своё приложение (Mi Fitness), оно же кладёт их в Health Connect на телефоне.
Пути наружу:

- **Облако производителя** — открытого API нет; выгрузка по запросу через поддержку идёт до 15
  рабочих дней и вручную.
- **Ручной экспорт Health Connect** (zip с SQLite) — ежедневно, но файл надо переносить руками.
- **Сторонние мосты** (Health Sync и подобные) — платные, данные идут через чужие сервисы,
  формат их, а не наш.
- **Своё приложение на телефоне** — читает Health Connect по его API в фоне и шлёт на наш сервер.

Health Connect хранит не всё, что меряет браслет: Mi Fitness не пишет туда пульс покоя, HRV,
частоту дыхания и стресс, а пульс вне тренировок — редкими точками. Сон с фазами, шаги, SpO2 и
пульс тренировок — пишет.

## Решение

- **Модуль `android/`** в этом репозитории: один экран (ссылка `…/#key=…` из `gym admin key
  --qr`, сервисный токен Cloudflare, разрешения) и `WorkManager` раз в час. Первый раз по
  каждому типу — все записи за два года (`READ_HEALTH_DATA_HISTORY`), дальше — изменения по
  токену Health Connect; токен сохраняется после успешной отправки, истёк (30 дней без сети) —
  полная выгрузка заново. Фон — `READ_HEALTH_DATA_IN_BACKGROUND`. Только чтение. Клиент API —
  общий `:client` с движком OkHttp.
- **Записи как есть.** Таблица `health_record`: ID записи Health Connect, тип, источник,
  интервал и вся запись в `data` (jsonb, `HealthRecord`). Повтор записи с тем же ID заменяет её,
  удалённые в источнике приходят списком ID. Протокол ревизий тренировок (ADR 0007) не нужен:
  телефон — единственный писатель, конфликтов нет.
- **Ночи и дни считает core при чтении** (`healthDays`): ночь дня — сон, закончившийся этим
  утром (окно 18:00–18:00 местного времени по смещению самой записи), куски с перерывом до
  90 минут — одна ночь, основной сон — самый длинный кусок, остальное — дрёма. У ночи один
  источник — у кого сна больше: два приложения не складываются. Шаги — больший из источников.
  Пульс ночью — минимум и медиана точек во время основного сна, если их от 10. Пульс покоя и
  HRV — только записанные источником, сами не выводим.
- **Исключённые дни** (`health_exclusion`): браслет носил другой человек — записи этих дней
  (по источнику или все) удаляются и больше не принимаются. Снять исключение — данные вернёт
  только повторная отправка.
- **Агенту — текст** (`HealthReport.toText`): `gym health days` и раздел `brief` «сон и
  восстановление за 28 дн.»: итог последней недели против трёх прошлых, последние 10 дней
  строкой. Старый сервер без `/api/health` `brief` не ломает.

## Почему

Своё приложение — единственный путь без участия владельца и без посредников: данные идут с
телефона прямо на свой сервер. Хранить записи, а не готовые ночи, — правила подсчёта ночи
можно менять без повторной выгрузки, а тесты core проверяют их на тех же записях. Модуль в
этом же репозитории — модель и клиент общие, правится одним изменением.

## Цена

Ещё одна платформа: Android SDK для сборки (без него модуль не включается в сборку; в образ
сервера папка не копируется), APK ставится вручную. AGP и Kotlin-плагин должны быть в одном
загрузчике классов — AGP объявлен в корне, а Quarkus перенесён в `server` (он поднимает JAXB
в общем classpath до 4, AGP нужен 2.3). Пульса покоя, HRV и стресса от Mi Fitness так не
получить — для них остаётся выгрузка из облака производителя.
