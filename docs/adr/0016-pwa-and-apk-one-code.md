# 0016. Клиент — PWA и APK из одного кода

Дата: 2026-11-21. Статус: принято. Дополняет 0003 (PWA на Compose/Wasm).

## Контекст

PWA рисует Compose в canvas браузера. Прокрутка и жесты на телефоне заметно уступают нативным:
в CLAUDE.md — обходы про `pointermove` и захват жеста в `Page`. ADR 0003 такой выход
предусматривал: тот же UI-код собирается под Android.

## Решение

- **Один UI-код — две сборки.** Экраны и `AppState` — в `app/commonMain`; всё, что трогает
  браузер или систему, — `expect` в `Platform.kt`. PWA — `wasmJsMain` (мост с `index.html`),
  APK — `androidMain` и модуль `android/` (`com.android.application`: KMP и приложение в одном
  модуле AGP 9 не пускает).
- **PWA остаётся**: для компьютера и запасной. На телефоне основное — APK.
- **Поведение одно.** Платформенное отличие допустимо там, где у системы своё средство: гифка —
  `AnimatedImageDrawable` вместо `<img>`, клавиатура — отступы окна, вход Cloudflare — сервисный
  токен в настройках вместо страницы входа. Сценарии и экраны общие.
- **Подключение APK** — общий экран `Connect`: ссылка `…/#key=…` задаёт сервер и ключ
  (ADR 0008), там же сервисный токен Cloudflare Access.
- **Хранилище APK** — файл на ключ через `AtomicFile`: запись целиком и до обновления экрана,
  как требует ADR 0007.
- **Подпись** — release-ключ владельца вне репо и образа. Потерян ключ — обновление не встанет,
  переустановка сотрёт неотправленное.

## Последствия

- APK отстаёт от сервера: пуш в `main` обновляет сервер и PWA сразу, APK — только после
  установки. Несовместимое изменение API — сразу новый APK, перед тренировкой не выкатывать.
- Общий код собирать под оба таргета (`:app:compileKotlinWasmJs :app:compileAndroidMain`).
- Доставка (SDK в Docker, релизы Gitea, Obtainium), замок одной тренировки на сервере и e2e на
  Android — `docs/PLAN-android.md`, этапы 3–5.
