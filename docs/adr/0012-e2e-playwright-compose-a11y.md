# 0012. Сквозные тесты: Playwright по дереву доступности Compose

Дата: 2026-11-05. Статус: принято.

## Решение

- Сквозные тесты — в `e2e/`, Playwright (Node). Один сценарий проходит обе стороны: агент
  пишет профиль и план через настоящий CLI `gym`, владелец проводит тренировку в PWA на
  эмуляции телефона (Pixel 7, `ru-RU`), агент читает результат через `gym compare` и
  `gym workout get`. Отдельный сценарий — офлайн: `context.setOffline(true)`, отметки в
  очереди телефона, после сети на сервере ровно по одной.
- **Управление PWA — через дерево доступности Compose.** Compose Multiplatform рисует в
  `<canvas>`, но выставляет семантику в DOM: shadow root → `#cmp_a11y_root`, узлы с ролями
  (`button`, `textbox`), текстами, `aria-label` из `contentDescription` и настоящими
  координатами. Слой прозрачный и нажатий не ловит, поэтому тест находит узел
  (`getByRole`/`getByText` пробивают открытый shadow root), прокручивает к нему колёсиком и
  нажимает мышью в центр рамки — нажатие получает canvas, как от пальца. Текст — с клавиатуры
  в сфокусированное поле (Compose держит скрытую `textarea`). Помощники — `e2e/lib.js`,
  класс `Phone`.
- **Иконки без текста подписаны** (`IconBtn(label = …)` → `contentDescription`): шестерёнка,
  кебаб «Меню: <упражнение>», сердечко, свернуть, таймер, стрелки порядка. Заодно их слышит
  экранный диктор.
- **Фото без системного диалога** — через уже существующий мост `index.html`: тест подменяет
  `window.bridge.pickPhoto` на `window.bridge.usePhoto(file)` с заранее нарисованным JPEG.
  Специального тестового кода в приложении нет.
- **Стенд на прогон** (`e2e/stand.js`, globalSetup): новый Postgres в Docker
  (`postgres:17-alpine`, случайный порт) и собранный сервер `quarkus-run.jar` на `E2E_PORT`
  (по умолчанию 7413), свой ключ через `TRAIN_BOOTSTRAP_KEY`, фото — во временную папку.
  После прогона сервер гасится деревом процессов, контейнер — `docker stop`. `E2E_URL`
  задан — стенд не поднимается, тесты идут в готовый сервер.
- Запуск — `./gradlew e2e` (собирает сервер с PWA и CLI, ставит зависимости и Chromium,
  гоняет тесты). В `build`/`check` не входит: нужны Docker и Node, прогон ~1,5 минуты.

## Почему

Ошибки, ради которых нужны сквозные тесты, живут на стыках: очередь телефона и протокол
синхронизации, привязка замера и фото к тренировке, исходы подходов в разборе агента. Их не
ловят ни тесты сервера, ни тесты ядра. Дерево доступности — единственный способ найти
элементы canvas-приложения по смыслу («кнопка Норм в строке Жима»), а не по пикселям, и оно
есть без изменений в приложении. Нажатие мышью по координатам проходит весь путь пальца:
жесты Compose, фокус, клавиатуру.

## Особенности, о которые спотыкается тест

- Семантику Compose обновляет с запаздыванием: после прокрутки и перерисовки координаты
  какое-то время старые. `reveal` ждёт, пока рамка узла не перестанет двигаться, `settled` —
  пока не перестанет меняться всё дерево.
- Тексты внутри нажимаемого контейнера сливаются в один узел (лист меню —
  «Удалить подходГоблет-присед · …»): проверки текста — подстрокой.
- У сфокусированного поля в дереве есть ещё узел курсора (`textbox` шириной 1 px):
  `getByRole('textbox').last()` может попасть в него. Поле ищется по геометрии — под
  заголовком (`fillBelow`).
- Строки подходов карточки — тоже по геометрии: всё между кебабом «Меню: <упражнение>» и
  следующей карточкой.

## Отвергнуто

- **Тестовые хуки в `window.bridge`** (нажать «Норм» у подхода N вызовом JS). Быстро и
  устойчиво, но мимо жестов, фокуса и раскладки — как раз того, что ломается на телефоне; и
  тестовый код в боевом приложении.
- **Чистые координаты по скриншотам.** Ломаются от любой правки вёрстки, не читаются.
- **Testcontainers** для стенда. Java-библиотека, тесты на Node: тот же `docker run` проще.
  Сервер в Docker-образе — дольше сборка; jar запускается за секунды.
- **Ручная проверка перед выкаткой.** Сценарий из десятков шагов, вручную его не проходят
  целиком.
