# 0011. Пользователи: админ и общий справочник

Дата: 2026-11-05. Статус: принято.

## Решение

- У пользователя флаг `admin`. Админ — пользователь из `TRAIN_BOOTSTRAP_EMAIL` (ставится при
  старте) и, при миграции V2, владелец, если он единственный пользователь. Видно в `GET /api/me`.
- **Новый пользователь** — только админ: `POST /api/admin/users {email, name?, keyLabel?}` →
  пользователь и его первый ключ (ключ показывается один раз). Почта приводится к нижнему
  регистру; уже есть — `409`. `GET /api/admin/users` — список. CLI: `gym admin user add <email>
  [--name] [--label] [--qr]` — ссылка `…/#key=…` и QR для телефона нового пользователя, как у
  `admin key` (ADR 0008). Почту надо добавить и в Cloudflare Access — это вне приложения.
- **Справочник общий + свои.** Упражнение без владельца (`owner_user_id is null`, `shared: true`)
  видят все; своё — только владелец. Админ по умолчанию добавляет в общий (`--own` — себе),
  остальные — только себе. Общее правит только админ, своё — владелец. V2 делает общим весь
  справочник единственного пользователя.
- Всё остальное — планы, тренировки, подходы, замеры, фото, профиль, ключи — изолировано: чужой
  id — `404`, как будто записи нет.

## Почему

Друг со своим телефоном — первый реальный второй пользователь. Без общего справочника каждому
пришлось бы заново собирать сотню упражнений с ru-названиями и долями веса тела, а агент правил
бы одни и те же ошибки в нескольких копиях. Права проще некуда — один флаг: ролей и групп не
нужно, пока пользователей двое-трое.

## Отвергнуто

- **Свой справочник у каждого с копированием при создании пользователя.** Копии расходятся,
  исправление названия или доли веса тела не доходит до остальных.
- **Заводить пользователей переменными окружения.** Нужен перезапуск, и ключ живёт в секрете
  Jenkins дольше, чем нужно.
