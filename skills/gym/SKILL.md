# gym

Владелец тренируется по плану с телефона (PWA `https://train.fil-lost.org`), ты ведёшь журнал через
CLI `gym`: пишешь планы, читаешь факт, решаешь, что дальше. Программы-шаблона нет — каждый план
ты составляешь заново из факта и истории. План — гипотеза: цикл **план → факт → compare →
следующий план**.

## Запуск

`gym`, если он в `PATH`, иначе `C:\java\my\train\cli\build\install\gym\bin\gym` (собрать —
`./gradlew :cli:installDist` в `C:\java\my\train`). Адрес и ключ — в `~/.config/gym/config`.
Вывод — JSON в stdout; ошибка — `{"error", "status"}` в stderr и код 1. Флаги и поля —
`gym <команда> --help`.

## Рабочий цикл

1. **Контекст.** `gym info` (связь и версия сервера), `gym profile get` — оборудование, правила
   владельца и рост (`equipment`, `notes`, `heightCm`); правила главнее твоих привычек. Затем `gym plan list --from <сегодня − 14 дней>`
   и `gym workout list --from <та же дата>`. Готово, когда знаешь: что запланировано, что сделано
   после последнего плана, какие планы `OVERDUE`.
2. **Разбор факта.** Для каждой тренировки после твоего последнего разбора — `gym compare <workoutId>`:
   подходы `DONE` / `SKIPPED` / `ADDED`, оценки (`EASY` / `NORMAL` / `HARD`), заметки, комментарий
   владельца, замены (`replacedFrom`), отметки времени. У упражнения — `liked: true` (сердечко:
   очень понравилось — оставляй в программе) и `comment` (заметка владельца к упражнению; `note` —
   твоя заметка из плана). `date` — день тренировки по телефону, `measurements` — замеры
   тренировки, `bodyweightKg` и `heightCm` — вес и рост. Готово, когда у каждого упражнения есть
   вывод: держать, добавить повторы, добавить вес, заменить — и почему; заметка владельца
   учтена.
3. **Просроченные.** У каждого плана `OVERDUE` судьба решается явно: перенести (`plan put --id`
   с новой датой) или убрать (`plan rm`). Скажи владельцу, что решил.
4. **Новый план.** Упражнения — из `gym exercise list`; нужного нет — `gym exercise search <слова>`
   (английский) и `gym exercise add <sourceId> --ru <название>`. Веса — от последнего факта:
   `gym exercise last <id>...`. Собери JSON (ниже), отправь `gym plan put <file>`, проверь
   `gym plan get <id>`. Готово, когда план на нужную дату виден в `plan list` со статусом `PLANNED`.
5. **Отчёт владельцу.** Коротко: что увидел в факте, что поменял в плане и почему.

## План

`{date, title?, body: {blocks, note?}}`. ID блоков, упражнений и подходов не нужны — сервер
сгенерирует. Каждая запись `plan put` — новая версия; `--id` (или поле `id`) — заменить план,
без него — новый.

- **Блок** — упражнения со своими списками целевых подходов + роль `WARMUP` / `MAIN` / `COOLDOWN`.
  Одно упражнение — обычные подходы, два — суперсет, больше — круг. Проходов столько, сколько
  подходов в самом длинном списке; круг может быть неровным.
- **Отдых**: `restSec` у упражнения — после его подхода; `restAfterPassSec` у блока — после
  закрытого прохода.
- **Тип записи** (`recordType`): `WEIGHT_REPS`, `REPS` (+ `extraWeight`), `TIME` (`seconds`),
  `WEIGHT_TIME`. Не указан — как у упражнения в справочнике. Дистанции нет: переноска — `TIME`
  или заметка.
- **Целевой подход**: `weight` — вес **одного** снаряда, кг; `repsMin`/`repsMax` — диапазон;
  `rir` — запас повторов. С `perSide: true` повторы и секунды — на каждую сторону.
- **Неизвестное — пропусти поле** (или `null`), не ставь ноль: пустое поле телефон
  предзаполнит из прошлого факта.

```json
  "date": "2026-11-07",
  "title": "B1",
  "body": {
    "note": "Поясница — по самочувствию, при дискомфорте мост вместо тяги",
    "blocks": [
      {"role": "WARMUP", "title": "Разминка", "items": [
        {"exerciseId": "<скакалка>", "recordType": "TIME", "sets": [{"seconds": 120}]}
      ]},
      {"role": "MAIN", "title": "Круг I", "restAfterPassSec": 120, "items": [

```

## Правила

- **Начатый план заморожен**: `plan put` на него — 409. Нужна правка — новый план на ту же дату.
- `startedVersion` меньше `version` — телефон начал старую версию офлайн, твоя правка не
  применилась. `compare` идёт по снимку, с которым начата тренировка; реши, что делать с планом.
- Удаление (`plan rm`) уводит в корзину; `gym trash purge --yes` стирает навсегда — только по
  прямой просьбе владельца.
- Упражнение справочника: у упражнения с собственным весом ставь `--bodyweight-factor`
  (отжимания 0.65, подтягивания 1, брусья 0.9, присед без веса 0.7), у двух гантелей —
  `--implements 2`, у одностороннего — `--per-side`.
- Замер: `gym measure add weight 81.5`; сделан на тренировке — `--workout <id>`. Вес тела входит
  в объём упражнений с долей веса тела: берётся взвешивание этой тренировки, иначе последнее до
  неё. Замеры тренировки — `gym measure list --workout <id>`.
- День в `--from`/`--to` у `workout list` — день по часам телефона (поле `date`), не UTC.
- Справочник: общий (`shared: true`, ведёт админ) + свои упражнения. `exercise add` у админа
  кладёт в общий, `--own` — только себе; не админу `--shared` даёт 403, общее он не правит.
- Фото прогресса: `gym photo list [--from] [--to] [--workout]`, `gym photo add <файл> --at
  <YYYY-MM-DD|ISO> --pose front|side|back [--note] [--workout]` (задним числом — через `--at`),
  `gym photo get <id> --out <файл>`, `gym photo edit`, `gym photo rm` (в корзину), `gym photo
  restore`. Принимаются JPEG, PNG, WebP, HEIC, до 15 МБ.
- Пользователи — только по просьбе владельца: `gym admin user add <email> [--name] --qr`
  выдаёт первый ключ и ссылку для телефона; ключ показывается один раз — передай его владельцу,
  в отчёт и файлы не пиши.
