## Зачем

Своё self-hosted приложение для учёта силовых тренировок, которым **полностью управляет агент**
(Claude, Codex) через API. Нечто среднее между GymKeeper, Hevy и Liftosaur: у каждого есть
понравившиеся фишки, но ни одно не даёт сразу удобного ввода на телефоне, кругов,
полного доступа агента и своих данных.

История выбора: wger (self-hosted) — «чудовищно неудобно менять на ходу», удалён; GymKeeper —
простой, есть CSV, нет API; Hevy — основной сейчас, официальный MCP только для ChatGPT
(OAuth с заранее выданным `client_secret`, Claude не подключить); Liftosaur — нравится
идеологически, интерфейс «прям не очень», MCP есть, но платный и облачный; GRAVL — отвратителен.

## Принципы

- **План → факт → история.** Агент задаёт, что сделать; владелец во время тренировки записывает,
  что сделал; анализ — сравнение трёх вещей: сколько предложено, сколько сделано, сколько делал
  раньше. План — гипотеза, недобор — данные, а не провал.
- **Прогрессию решает LLM**, видя историю, текущий срез, разницу «предложено/сделано» (в том числе
  в прошлом) и оценки владельца. Автопрогрессии по формуле в приложении нет. Отдых, веса, число
  подходов и проходов — тоже решения агента.
- **Всё, что видно в интерфейсе, доступно через API**, включая удаление и правку завершённых
  тренировок, замеры и фото.
- **Self-hosted, данные свои**, без лимитов и подписок.
- **Без коммерции** — ни сейчас, ни в перспективе. Для коммерческого использования понадобились бы
  свои медиа или купленная лицензия.

## Рабочий цикл

Агент генерирует тренировки на указанные дни → владелец проходит их и записывает факт →
агент анализирует (факт против плана, история, оценки, комментарий) и генерирует следующие.
Программы-шаблона нет: каждая запланированная тренировка — конкретная сессия на дату.

## Экран тренировки (телефон)

Согласован на макете. Тёмная тема, средние тач-зоны.

- **Блоки сверху вниз** с видимыми разделителями, не вкладки: разминка → круги → заминка. Каждый
  блок — свой приглушённый оттенок: разминка зелёная, заминка оранжевая, круги — разные оттенки
  по очереди. В заголовке круга — «× 3 · проход 2 из 3».
- **Карточка упражнения**: пиктограмма из медиа-пакета (нет медиа → заглушка), название, цель из
  плана и отдых, точки прогресса по подходам. Тап по пиктограмме — gif и техника.
- **В свёрнутой карточке видна строка следующего подхода** — первого невыполненного у этого
  упражнения, под номером «из N» (всего подходов). По кругу идёшь одним тапом по оценке в каждой
  карточке. В круге карточка показывает подход, только когда до упражнения дошёл проход: отметил
  свой — карточка свернулась и ждёт остальные упражнения. Только что отмеченный подход остаётся
  над следующим, пока не отмечен другой: иначе на его месте встаёт такой же подход с теми же
  значениями и кажется, что оценка не нажалась. Тап по названию раскрывает все подходы (отметить
  можно любой) и «+ подход».
- **Проход** = подходы с одним номером у всех упражнений блока. Круг может быть неровным.
  «Проход k из N»: k — наименьший номер с невыполненным, N — самый длинный список подходов.
- **Строка подхода**: № и время отметки · прошлый результат · поля (по типу записи) · Легко / Норм
  / Тяжело. **Тап по оценке = подход выполнен** с текущими значениями. Значения правятся до и после
  отметки; повторный тап по той же оценке снимает отметку. Правка одного подхода на другие
  не распространяется.
- **Предзаполнение как в Hevy**: значения из целевого подхода плана; чего в плане нет — из прошлого
  факта на том же номере подхода.
- **Шапка**: свернуть, общее время, таймер/секундомер (пресеты, ±15 с), «Завершить» — одна
  кнопка, внизу списка её нет. «Сброс» секундомера обнуляет и останавливает.
- **Отдых**: после отметки внизу полоска с обратным отсчётом от отдыха из плана. Отметка закрыла
  проход (все подходы с этим номером в блоке выполнены) → отдых после прохода, иначе → после
  упражнения. Решает состояние, а не позиция в списке. Не блокирует, ±15, скрыть. В круге без
  отдыха в плане — открытый отдых: счёт вверх («Отдых между упражнениями» / «после прохода»), без
  выдуманного числа; у одиночного упражнения без отдыха полоски нет. Конец отдыха и ручного таймера
  — вибрация и короткий звук (Web Audio, разблокируется первым касанием), и на экране техники тоже.
  Вибрация выключена по умолчанию (настройка профиля; приложение её пока не читает).
- **Поля значений** — цифровая клавиатура: дробная для веса, numeric для повторов и секунд.
  Compose ставит скрытому полю `inputmode="number"` — такого значения нет, index.html правит его
  на `numeric`.
- **Вернулся с техники** — экран тренировки на том же месте: прокрутка и раскрытые карточки
  хранятся, пока экран в стеке навигации.
- **Меню упражнения**: техника и мышцы, заменить, добавить / убрать невыполненный подход, удалить
  выполненный (выбор из списка; в разборе плановый станет пропущенным), сменить тип записи
  (скакалка: время ↔ повторы), режим порядка, убрать из тренировки. «+ упражнение в блок» —
  из справочника, сначала недавние.
- **Завершение**: время, подходы из плана, объём, темп, комментарий для агента, приглашение
  записать замеры.
- Разбирать, что пошло не по плану, — задача агента по натыканным данным, а не интерфейса.

Остальные экраны среза: главная (сегодня / ближайшие / просроченные, плашка активной
тренировки), просмотр плана с «Начать», история (список и «факт против плана»), замеры.

## Модель данных

- **Пользователь.** У всех личных данных есть владелец (см. «Многопользовательность»).
- **Упражнение** (справочник): ru- и en-название, мышцы основные и вспомогательные с
  коэффициентами, оборудование, тип записи по умолчанию, односторонность («на сторону»), ссылка на
  медиа и на запись источника. Справочник общий + личные упражнения.
- **Тип записи**: `вес × повторы`, `повторы` (+ доп. вес), `время`, `вес × время`; дистанция —
  потом. В плане и тренировке переопределяется на месте; сделанные подходы сохраняют свой.
- **Вес — одного снаряда** (одной гантели), у упражнения поле «снарядов: 1 / 2». Повторы
  «на сторону» — на каждую сторону. У упражнения с собственным весом — **доля веса тела**
  (отжимания ≈ 0,65, подтягивания ≈ 1), её ставит агент. Объём = (вес × снарядов + вес тела ×
  доля) × повторы, ×2 если «на сторону»; вес тела — последний замер до тренировки.
- **Запланированная тренировка** на дату → блоки → упражнения → целевые подходы (вес, диапазон
  повторов, секунды, запас повторов) + отдых после упражнения и после прохода.
  - **Блок** = упражнения, у каждого свой список целевых подходов, + роль (разминка / основной /
    заминка). Главное — списки подходов; число проходов — длина самого длинного. Обычные
    подходы — блок из одного упражнения, суперсет — из двух. Роль — свойство места, не упражнения.
  - Всё варьируется свободно: пирамиды, число подходов, веса, повторы.
  - Дата — намерение, начать можно в любой день. До старта агент правит план, каждая правка —
    новая **версия** (старые хранятся). **После старта план заморожен.** Не начатый в срок —
    «просроченный», решает агент.
- **Тренировка (факт)** → блоки → упражнения → фактические подходы (значения, оценка, заметка,
  время отметки) + комментарий владельца.
  - При старте тренировка берёт **снимок** целей своей версии плана; подходы и `compare`
    опираются на снимок. Агент поменял план, пока телефон офлайн начинал старую версию →
    тренировка принимается целиком, план помечается, решает агент (ADR 0007).
  - Факт подхода хранит (блок, упражнение, номер подхода), ссылку на цель, если была, и **свои**
    упражнение, тип записи и «на сторону» — смысл факта не меняется при правке раскладки или
    справочника (ADR 0006). Добавленный — без ссылки, пропущенный плановый — без факта.
  - **Замена** после нескольких подходов: сделанные остаются со старым упражнением, новые — с
    новым, цель та же, раскладка помнит `replacedFrom`.
  - **У каждого подхода — время отметки** → настоящая хронология кругов, темп и фактический отдых.
  - Одна активная тренировка за раз; переживает перезапуск приложения; забытую предлагается
    закрыть временем последней отметки + 5 мин.
- **Замер** (тип, значение, единица, время, опционально — тренировка).
- **Фото** (ключ в хранилище, ракурс, время, опционально — тренировка или замер).
- **Оборудование**: блины, грифы, потолок веса. Пример владельца: разборные гантели до 15 кг,
  перебирать не больше 1–2 раз за тренировку. В MVP — профиль, который читает агент.
- Единицы — только кг. Неизвестное не выдумываем: нет значения → пусто, а не ноль.
- ID генерирует клиент (UUIDv7) — без этого не работает офлайн.
- Удаление и снятие отметки — состояние записи (`deleted`, `done`), а не стирание: так их можно
  синхронизировать (ADR 0007).

## Аналитика

- `gym compare <workout>` — план против факта по тренировке, с историей упражнений.
- **Нагрузка — три числа, а не одно.** Универсальной «тяжести» нет: 10 кг × 10 в махах и в
  приседе — один тоннаж и разная нагрузка. Выводы делает агент:
  - **объём** (тоннаж с долей веса тела) — для динамики одного упражнения и тренировок похожего
    состава на длинных отрезках;
  - **рабочие подходы** — сделанные подходы в основных блоках; сравнимы между упражнениями,
    через мышцы — основа звёздчатой диаграммы;
  - **время под нагрузкой** — подходы на время (скакалка, планка), в килограммы не переводятся.
  Потом, на импортированной истории, — индекс «относительно своего лучшего» в упражнении.
- **Статистика нагрузки за период**, по умолчанию — месяц:
  - **звёздчатая диаграмма** по частям тела — куда сколько нагрузки, видны перекосы;
  - **схема тела** спереди и сзади: мышцы, которые были в работе, подсвечены; чем ярче, тем
    сильнее проработана мышца за период.
  `gym volume --period` отдаёт те же цифры агенту в JSON.
- Коэффициенты объёма решаем, когда дойдём до статистики и будет импортирована история.
  Ориентир Liftosaur: основная мышца ×1, вспомогательная ×0,5, 10–20 подходов в неделю.
  Коэффициенты настраиваемые и подстраиваются по обратной связи. Таксономия мышц датасета
  грязная (`traps`/`trapezius`, `delts`/`deltoids`) — нужен свой канонический список с
  маппингом, он же — области на схеме тела.
- **Темп тренировки** = общее время / общий объём нагрузки, а не соблюдение таймера отдыха.

## API, CLI, агенты

- **REST API** (OpenAPI): полный CRUD всего. PWA ходит через тот же API.
- **Агент пишет и читает JSON** (ADR 0005): планы по схеме, история и аналитика — тоже JSON.
- **CLI `gym` — тонкий клиент к REST** (ADR 0002). Аналитика считается на сервере, логика —
  в общем модуле `core`.
- **Модули Gradle**: `core` (KMP: DTO, аналитика), `server` (Quarkus), `cli` (JVM), `app`
  (Compose, Wasm).
- **Скилл для агента** с описанием команд, JSON-схем и рабочего цикла.
- Удаление — в корзину; окончательное стирание — отдельным действием (защита от ошибки агента).
- **MCP — не в MVP.** Добавить, когда понадобится доступ с телефона или из веба.
- **Осознанное ограничение:** агент недоступен прямо в приложении и в чате с Claude с телефона.

## Бэкенд

**Quarkus на Kotlin** (ADR 0001): `quarkus-rest` + `kotlinx.serialization`, Hibernate ORM +
Panache Kotlin, Flyway, SmallRye OpenAPI, Dev Services для Postgres в разработке.

## Клиент

**PWA на Compose Multiplatform, таргет Kotlin/Wasm** (ADR 0003), телефон — Android. Ставится на
экран как приложение, не даёт гаснуть экрану во время тренировки (wake lock).

- **Офлайн** (ADR 0007): активная тренировка, планы на ~2 недели вперёд и очередь неотправленного
  живут в телефоне. Тренировка и очередь — один документ, пишется атомарно на каждое действие.
  Очередь хранит последнее состояние каждой записи; сервер ведёт версии (`rev`), повтор
  отправки безопасен (`opId`), часы телефона в конфликтах не участвуют. Во время тренировки
  побеждает телефон, в завершённой — сервер. Писать может одна вкладка.
- **Подключение** (ADR 0008): ключ вводится или сканируется QR при первом запуске, меняется в
  настройках. Приложение различает «нет сети», «нужен вход в Cloudflare», «ключ не принят»,
  «ошибка сервера» и «конфликт».
- Compose for Web — Beta. **Первый шаг работы — проверка на телефоне** (ввод чисел, клавиатура,
  офлайн-запуск, wake lock, gif, ручной редирект в HTTP-клиенте). Не пройдёт — тот же UI-код собирается под Android.
- Telegram-бот — возможное дополнение потом (прислать план, напомнить про замеры), не клиент.

## Хранение

- **Postgres — единственный источник правды.** Тело плана и раскладка тренировки — `jsonb`,
  фактические подходы — строки (ADR 0006).
- **Фото — Garage** (лёгкое S3-совместимое хранилище, `quarkus-amazon-s3`). В БД — ключ и
  метаданные. MinIO и SeaweedFS — избыточны.
- **Бэкап:** регулярный дамп базы + экспорт всего в JSON/CSV по пользователям.

## Деплой и доступ

- **Один `compose.yaml`:** бэкенд (раздаёт и PWA, и медиа) + Postgres + Garage.
- Домашний сервер, наружу через **Cloudflare Tunnel** (HTTPS от Cloudflare, порты на роутере не
  открываем). Tailscale отвергнут: держать его включённым на телефоне напрягает.
- **Авторизация в два слоя, всё закрыто, включая фото:**
  1. **Cloudflare Access** перед туннелем. Телефон — вход через Google или код на почту, сессия
     около месяца. CLI и агенты — сервисный токен.
  2. **API-ключ приложения** — второй слой на случай ошибки в настройке Cloudflare.
  Своих паролей и экрана входа не пишем. Истёкшая сессия посреди тренировки → подходы ждут
  в офлайн-очереди.
  Есть JWT Access → его почта должна совпасть с владельцем ключа, иначе `403`; у сервисного
  токена почты нет — пользователя задаёт ключ. Картинки и фото грузит HTTP-клиент приложения с
  ключом, gif — через `blob:`-URL (ADR 0008).
- В первом срезе — только API-ключ и локальная сеть; Cloudflare — при деплое. Service worker и
  wake lock требуют HTTPS, поэтому до Cloudflare — флаг Chrome на телефоне или `adb reverse`
  (см. PLAN, шаг 0).
- **CI/CD — как в `c:\java\my\mediabots\`:** код в Gitea (`mess9/train`), Jenkins pipeline
  из SCM. `Jenkinsfile`:
  1. сборка образа и тесты;
  2. push в `localhost:5000/mess9`;
  3. `docker compose up` прямо из workspace;
  4. smoke-тест;
  5. уведомление в n8n.

  Секреты живут только в Jenkins credential `train-env` (Secret file); список переменных — в
  `train.env.example`. Тома в `compose.yaml` — абсолютные пути хоста: compose запускается
  из контейнера Jenkins.

## Многопользовательность

Сразу на много пользователей — не потому что планируется делиться («скорее всего нет»), а потому
что однопользовательская архитектура некрасива.

- `user_id` у всех личных данных; API-ключи на пользователя; ключи фото с префиксом пользователя;
  экспорт по пользователю.
- Cloudflare Access пускает почты из списка; почта из JWT Access → пользователь в приложении.
- **MVP: изолированные аккаунты**, каждый видит только своё. Обмен планами и просмотр чужого
  прогресса — позже, модель должна это позволять.

## Упражнения и медиа

Пиктограмма рядом с названием + gif по тапу, чтобы одним взглядом понять технику, не идя в гугл.

- **Источник** — `c:\java\my\exercises-dataset\` (hasaneyldrm/exercises-dataset): 1324 упражнения,
  en-названия, инструкции и шаги на 10 языках (есть ru), мышцы, оборудование, jpg + gif.
  Атрибуция Gym visual — для личного некоммерческого использования.
- **Справочник ≠ источник.** В справочник упражнения добавляются **по запросу**: сначала несколько
  десятков базовых (агент собирает из истории Hevy/GymKeeper и под оборудование), потом по мере
  надобности. Агент ищет по всему датасету и добавляет с ru-названием. С телефона — поиск только
  по справочнику, сначала недавние.
- **Медиа — заменяемый пакет**: папка, смонтированная в контейнер, отдельно от справочника.
  Нет медиа → заглушка-пиктограмма.

## Импорт истории

Источники: Hevy JSON по тренировкам, сохранённые планы `*.hevy-routine-proposal.json`, полный CSV
GymKeeper (лежат в личном хранилище владельца, `knowledge/training-data/`).

- Планы тоже импортируются и связываются со своими тренировками — сравнение «предложено /
  сделано» работает и на старой истории.
- Повторный импорт идемпотентен по исходному ID. Мусорная запись GymKeeper от 28.09.2025
  пропускается.
- Времени подхода и RPE в старых данных нет → пусто, а не ноль.
- **Механизм:** Codex выгружает через MCP всё, что доступно, в файлы. Claude приводит их к
  формату API и заливает в базу. Чего по MCP не достать — владелец вписывает вручную в тот же
  формат.
- Идемпотентность — через детерминированный ID: UUIDv5 от источника и исходного ID.
  Отдельная колонка не нужна.

## Объём работ

**Первый срез («вечер»)** — см. [docs/PLAN.md](docs/PLAN.md): справочник по запросу с медиа из
датасета, планы и тренировки с блоками × проходами, экран тренировки на PWA с офлайн-очередью,
главная / план / завершение / история / замеры, REST API, CLI, скилл, API-ключ, мультиюзерная схема,
docker-compose (бэкенд + Postgres).

**Следующие итерации:**
- CI/CD в Jenkins;
- Cloudflare Tunnel + Access;
- импорт истории;
- статистика: звёздчатая диаграмма и схема тела;
- фото и Garage;
- подсказки весов по оборудованию;
- экспорт;
- поиск по датасету с телефона;
- дистанция в типах записи.

**Не в MVP:** MCP, OAuth для веб-коннекторов, обмен между пользователями, Telegram-бот, редактор
планов и свободная тренировка без плана в UI.
